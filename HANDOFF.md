# In-flight work on `argus-2`

## Two things need you before the forms can send

`npm install` in `backend/` is **done** — `nodemailer` and `@types/nodemailer`
are installed, the backend typechecks, and lint is back to zero errors.
`backend/package-lock.json` changed as a result and has to go in the same
commit as `backend/package.json`, or the next person to install gets a
lockfile that does not mention nodemailer and hits the same lint failure.

1. **SMTP credentials**, as backend environment variables. Without them
   inquiries are still stored, just not mailed:
   - `SMTP_HOST`, `SMTP_PORT` (587, or 465 for implicit TLS)
   - `SMTP_USER`, `SMTP_PASSWORD`
   - `SMTP_FROM` — must be a domain you are allowed to send as. Defaults to
     `AssistSec <noreply@assistsec.nl>`.
   - `INQUIRY_RECIPIENT` — defaults to `contact@assistsec.nl`.
2. **The migration.** The `inquiries` table exists in
   `backend/src/db/schema.ts` but has no migration yet. Run `npm run db:generate`
   then `npm run db:migrate` in `backend/`. Migrations are generated by
   drizzle-kit, never hand-written.

## How "100% of inquiries get received" is actually achieved

The row is written to the database **before** any mail is attempted, and the
HTTP response does not depend on delivery. So a mail provider that is down,
throttling, misconfigured or simply not set up yet cannot lose an inquiry: it
leaves a row with a null `delivered_at`, which is the queue of things still to
send. Delivery alone was not a safe promise to make; storage plus delivery is.

`SELECT * FROM inquiries WHERE delivered_at IS NULL ORDER BY created_at;` is the
list of anything that has not gone out.
